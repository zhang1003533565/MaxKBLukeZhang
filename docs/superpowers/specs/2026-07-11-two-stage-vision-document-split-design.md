# 双模型图文分段设计

## 目标

将现有由单个视觉模型直接完成图文理解和最终分段的流程，改为两个可配置模型协作：视觉理解模型负责按页识别、筛选原始插图并生成图片说明，文本分段模型负责对增强后的图文文本进行最终语义切分。

模型只按 MaxKB 模型类型选择，不绑定具体厂商或型号：

- 视觉理解模型必须是 `IMAGE` 类型。
- 文本分段模型必须是 `LLM` 类型。

最终保留 PDF 中的原始有效插图，不保存页面截图，不新增 PDF 渲染依赖。

## 范围

本次仅调整上传文档时的“大模型图文分段”流程，包括上传界面、文档切分 API、PDF 图片候选筛选、视觉理解、文本分段和测试。

不修改数据库结构，不新增依赖，不改变智能分段、高级分段和大模型文本分段的既有行为。

## 用户交互

“大模型图文分段”选中后显示两个必选模型选择器：

1. 图文理解模型：只展示 `IMAGE` 类型模型。
2. 文本分段模型：只展示 `LLM` 类型模型。

缺少任意模型时禁用“生成预览”。上传草稿分别保存两个模型 ID，刷新页面后恢复选择。

“大模型文本分段”继续只选择一个 `LLM` 类型模型。

## API 合约

文档切分接口新增两个可选字段：

- `vision_model_id`：图文理解阶段使用的 `IMAGE` 类型模型 ID。
- `llm_model_id`：最终语义切分阶段使用的 `LLM` 类型模型 ID。

校验规则：

- `split_strategy=llm_vision` 时两个字段都必填。
- `vision_model_id` 对应模型类型必须为 `IMAGE`。
- `llm_model_id` 对应模型类型必须为 `LLM`。
- `split_strategy=llm_text` 继续接受现有 `model_id`，保持接口兼容。
- 旧客户端对 `llm_vision` 只提交 `model_id` 时返回明确参数错误，不把一个模型同时用于两个阶段。

## 数据流

### 1. PDF 基础解析

PDF 解析器继续按页提取文字和原始图片对象，并为每张候选图片创建稳定的临时图片 ID。候选图片仍与页码关联，不在视觉判断前写入最终段落。

非 PDF 文档沿用现有图片引用和段落解析方式；只有能够建立图片与文本上下文关系的内容进入视觉阶段。

### 2. 确定性预过滤

在调用视觉模型前，仅删除能够可靠判断为无意义的图片：

- 空字节或无法解码的图片。
- 宽或高小于 16 像素的图片。
- 总像素少于 1024 的图片。
- 宽高比大于 30:1 或小于 1:30 的线条型图片。
- 完全透明的图片。
- 近似单色且没有明显纹理变化的图片。

过滤规则保持保守：无法确定时保留给视觉模型判断，避免误删流程图、二维码、代码截图或小型图标示例。

### 3. 视觉理解

视觉模型按页处理。每次请求包含：

- 文档名和页码。
- 当前页提取文字。
- 最多 4 张带稳定候选 ID 的原始图片。

同一页超过 4 张候选图片时拆成多批，重复提供相同页文字。视觉模型只负责图片分类和描述，不负责最终分段。

视觉模型必须输出 JSON：

```json
{
  "images": [
    {
      "id": "candidate-id",
      "keep": true,
      "description": "图片展示的知识内容",
      "reason": "保留或丢弃原因"
    }
  ]
}
```

判定规则：

- 知识插图、流程图、表格、代码截图、软件操作截图、示意图保留。
- 背景、装饰、页眉页脚图案、水印、遮罩、纯色块、重复图片和没有知识信息的图片丢弃。
- `keep=true` 时 `description` 必须是非空、有检索价值的说明。
- 模型返回未知 ID、遗漏当前批次 ID、重复 ID 或无效 JSON 时，本批次失败。

### 4. 图片持久化与增强文本

只有 `keep=true` 的原始图片写入文件存储并生成 `./oss/file/<id>` 引用。丢弃图片不进入段落，也不保留孤立文件记录。

每张保留图片在原页文本附近追加说明和原图引用：

```markdown
图片说明：流程图展示源代码经过 Python 解释器后产生运行结果。

![image](./oss/file/<id>)
```

纯图片页面只有在至少一张图片获得有效说明时才进入后续分段；没有文字且所有图片均被丢弃的页面不生成段落。

### 5. 文本模型最终分段

文本分段模型接收按页汇总的增强文本，按现有字符批次限制调用，输出现有段落 JSON 结构：

```json
{
  "paragraphs": [
    {
      "title": "段落标题",
      "content": "段落正文和原始图片引用"
    }
  ]
}
```

约束：

- 单段建议 150～500 字，并受用户设置的最大分段长度约束。
- 图片必须与其说明和相关正文处于同一语义段落。
- 不允许创建、修改或重复图片 ID。
- 不允许输出只含图片引用、没有说明文字的段落。
- 后端校验输出图片 ID 集合必须与输入保留图片集合一致；校验失败则整次预览失败。

## 失败与清理

任意视觉批次或文本分段批次发生以下情况时，整次预览失败：

- 模型调用异常。
- 返回内容不是有效 JSON。
- 图片判定结果缺失或包含未知 ID。
- 最终段落新增、丢失、修改或重复图片引用。

失败时清理本次请求创建但未形成成功预览的图片文件和文件记录，不返回部分结果。前端沿用现有失败状态并允许用户重新生成预览。

## 兼容性

- 智能分段、高级分段不变。
- 大模型文本分段继续使用现有单模型流程和 `model_id`。
- 大模型图文分段改为双模型必选，不复用旧的单视觉模型语义。
- 不修改已保存文档、既有段落和数据库表结构。
- 已生成的旧预览不会自动迁移，重新生成预览后使用新流程。

## 测试

后端测试覆盖：

- 双模型字段必填及模型类型校验。
- 候选图片与页码关联。
- 明显无效图片的确定性过滤。
- 每批最多 4 张图片及同页拆批。
- 视觉 JSON 正常、缺失、重复、未知 ID 和无效 JSON。
- 只持久化保留图片。
- 图片说明与原图引用进入增强文本。
- 文本模型输出图片 ID 守恒校验。
- 任一阶段失败时清理临时图片。
- `llm_text` 旧接口兼容。

前端检查覆盖：

- 图文分段显示两个模型选择器。
- 两个模型未同时选择时禁用预览。
- 草稿保存和恢复两个模型 ID。
- 请求分别提交 `vision_model_id` 与 `llm_model_id`。

验收标准：使用包含正文、知识插图、背景和装饰元素的 PDF 生成预览后，不出现背景或装饰图片，不出现纯图片无说明段落；有效原始插图均有说明并与相关文字处于同一段落。
