# PDF 图片预览修复设计

## 目标

PDF 文档解析后，段落中的图片引用必须指向已保存的 OSS 文件，而不是 `image_页码_序号` 占位符，使分段预览、普通文本分段和图文模型均可读取图片。

## 方案

在 `PdfSplitHandle` 中集中提取整个 PDF 的图片。每张图片创建一个尚未落库的 `knowledge.models.File`，把图片二进制放入 `meta.content`，再通过现有 `save_image` 回调统一保存。解析器按页生成 `![image](./oss/file/<UUID>)`，并把这些引用注入对应页面文本。

普通正文解析、目录解析、内部链接解析和 `get_content` 共用同一份按页图片映射，避免重复提取和重复保存。单张图片提取失败时记录警告并继续处理其余内容。

## 兼容性与约束

- 不修改数据库结构。
- 不新增依赖。
- 保持 `save_image` 现有契约和 OSS URL 格式。
- 已经生成的旧草稿不会自动修复，需要重新生成预览。
- 不修改前端 Markdown 渲染逻辑。

## 验证

- 回归测试证明图片会转成 `./oss/file/<UUID>`，且不再出现 `image_0_0`。
- 回归测试证明提取的 `File.meta.content` 保存原始图片字节。
- Ruff、Django check 和仓库规则校验通过。
