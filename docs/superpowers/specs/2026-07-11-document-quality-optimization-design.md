# 文档分段质量优化设计

## 目标

在现有文档图文切分流程上增加可选的“高质量优化”，同时覆盖两个入口：

1. 上传预览页：导入前优化当前分段草稿；
2. 已导入文档详情页：生成优化草稿和前后对比，用户确认后才覆盖原段落并重新向量化。

基础清洗保持默认执行；会增加模型调用的语义优化必须由用户主动开启或点击。

## 设计原则

- 原文事实、代码、URL 和图片引用不可丢失或新增。
- 规则能够确定处理的内容不交给模型。
- 模型只负责主题边界、相邻段落合并、超长段落拆分和标题重写。
- 优化结果必须经过质量门禁；不合格批次回退到优化前内容。
- 已导入文档不直接覆盖，必须先预览并由用户确认。
- 不修改数据库结构，不新增依赖。

## 总体流水线

```text
原始分段
  → 确定性清洗
  → 段落质量分析
  → 生成待优化批次
  → 文本模型语义优化
  → 确定性质量门禁
  → 合格结果 / 原批次回退
  → 优化报告与对比预览
```

视觉模型仍负责图片筛选和说明，不参与最终文本段落重写。文本优化模型复用用户在“文本分段模型”中选择的 LLM。

## 第一层：确定性基础清洗

基础清洗默认执行，且不增加模型调用。

### 删除内容

- 带明确页标识的页码，例如 `第 15 页`；独占数字可能是代码输出，不自动删除；
- 已知模板水印，例如 `www.themegallery.com`；
- 只有装饰意义的连续分隔符；
- 重复的相邻标题行；
- 图片引用附近重复出现的相同图片说明。

### 规范化内容

- 将 PowerPoint 私有项目符号 ``、``、``、`` 等统一为 `- `；
- 连续三个以上空行压缩为两个；
- 清理行尾空白和无意义制表符；
- 保留 Markdown 图片引用、URL、命令、代码行和原始换行结构。

基础清洗必须是幂等操作，同一内容重复执行不会继续发生变化。

## 第二层：段落质量分析

每个段落生成只用于本次任务的质量指标：

- `length`：正文字符数；
- `image_count`：图片引用数量；
- `fallback_image_count`：未识别图片说明数量；
- `noise_count`：页码、水印、私有符号残留数量；
- `generic_title`：标题是否属于“Python实例（一）”“示例”“其他”等低区分度标题；
- `too_short`：清洗后少于 120 字且不是纯代码/纯图片说明；
- `too_long`：超过 900 字；
- `hard_too_long`：超过 1400 字。

目标段落长度为 200～800 字。长度不是唯一判断条件，图片操作流程、完整代码示例和表格允许在 900 字以内保持完整。

## 第三层：语义优化

只将存在以下问题的段落送入文本模型：

- 标题区分度低；
- 段落过短，需要与前后相邻主题合并；
- 段落过长，需要按子主题拆分；
- 一个段落明显包含两个以上标题或主题；
- 相邻段落标题和主题高度重复。

模型输入以相邻窗口为单位，每批包含目标段落及最多一个前后上下文段落。图片引用使用短别名 `img_n`，模型输出后再映射回真实文件 ID。

模型输出严格为：

```json
{
  "paragraphs": [
    {
      "title": "能够直接表达知识点的标题",
      "content": "优化后的正文"
    }
  ]
}
```

提示词明确要求：

- 不总结、不扩写、不纠正原文事实；
- 不修改代码、命令、URL 和图片说明；
- 不新增、删除、重复或移动到无关主题的图片引用；
- 标题控制在 4～40 个字符；
- 避免“实例（一）”“其他”“概述”等无法独立检索的标题；
- 每段只表达一个主要知识主题。

## 保护内容

优化前提取保护项并建立多重集合：

- Markdown 图片引用；
- URL；
- 以 `>>>`、`...` 开头的交互式代码行；
- `import`、`from`、`def`、`class`、`print(`、`pip install` 等明显代码或命令行；
- Markdown 代码块；
- 图片说明文本。

模型输出必须保留完全相同的保护项集合。任何缺失、新增、重复或内容变化都会导致该批回退。

## 质量门禁

每批模型输出依次验证：

1. JSON 结构有效，标题和正文非空；
2. 图片引用多重集合完全一致；
3. URL、代码、命令和图片说明的保护项多重集合完全一致；
4. 不产生超过 1400 字的段落；
5. 不产生少于 80 字的普通文本段落；
6. 标题长度为 4～40 字；
7. 标题不命中低区分度标题规则；
8. 去除空白后输出正文必须与输入正文完全一致，模型只能调整边界和标题；
9. 输出正文总长度相对输入变化不超过 15%，忽略已确认删除的噪声。

门禁失败时只回退当前批次，不影响其他批次。优化报告记录失败原因，但不向前端暴露模型供应商原始响应。

## 未识别图片处理

“视觉模型未能识别，已保留原始插图”的图片继续保留，不在文本优化阶段删除。

质量报告单独统计这些图片，并在预览中标记为“建议人工检查”。后续可由用户在段落编辑器中删除或补写说明。本阶段不再次调用视觉模型，避免费用和处理时间不可控。

## 上传预览入口

在“大模型图文分段”配置中增加“高质量优化”开关，默认关闭。

关闭时：

- 执行基础清洗；
- 保持现有视觉识别和文本切分流程。

开启时：

- 视觉识别和首次文本切分完成后进入 `quality_analyzing`、`quality_optimizing`、`quality_validating` 三个进度阶段；
- 复用当前文本分段模型；
- 预览结果附带质量报告摘要。

报告展示：优化前后段落数、清理噪声数、重写标题数、拆分数、合并数、回退批次数、未识别图片数。

## 已导入文档入口

在文档详情页增加“质量优化”按钮。

点击后：

1. 选择文本优化模型；
2. 启动异步优化任务；
3. 展示处理进度和终止按钮；
4. 完成后打开前后对比预览；
5. 用户选择“应用优化”或“放弃草稿”。

优化草稿存入缓存，TTL 为 2 小时，不写入正式段落表。草稿包含原段落 ID、优化前快照、优化后段落及质量报告。

“应用优化”时在数据库事务中：

- 再次校验原段落更新时间，避免覆盖用户在优化期间做出的编辑；
- 替换当前文档段落；
- 保留原有图片文件引用；
- 重新生成段落向量；
- 删除优化草稿。

若原文已发生变化，拒绝应用并提示重新生成优化草稿。

## 异步任务与取消

上传预览复用现有 split preview Celery 任务和强制终止能力。

已有文档优化使用独立 Celery 任务，但复用相同的缓存状态字段、轮询组件、cancelled tombstone 和 `revoke(terminate=True)` 语义。取消后只删除优化草稿，不删除正式文档和正式图片。

## API 设计

上传预览现有请求增加：

```text
quality_optimize=true|false
```

已有文档增加：

```text
POST   .../document/{document_id}/quality/task
GET    .../document/{document_id}/quality/task/{task_id}
DELETE .../document/{document_id}/quality/task/{task_id}
POST   .../document/{document_id}/quality/task/{task_id}/apply
```

所有接口校验用户、工作区、知识库、文档和任务归属。不存在与无权访问统一返回 404。

## 前后对比

对比预览按变化类型分组：

- 标题重写；
- 段落拆分；
- 段落合并；
- 噪声清理；
- 未改变；
- 门禁失败并回退。

每组展示优化前后标题、字符数、图片数和正文。默认折叠“未改变”，优先展示发生变化及需要人工检查的段落。

## 错误处理

- 单批模型返回无效：重试一次，仍失败则回退该批；
- 模型鉴权、余额、网络等调用错误：任务失败，不覆盖任何正式内容；
- 质量门禁失败：回退当前批并继续；
- 缓存过期：草稿不可应用，正式内容不受影响；
- 应用时原段落变化：拒绝覆盖；
- 向量生成失败：数据库事务回滚，保留原段落和原向量。

## 测试

后端覆盖：

- 基础清洗幂等性及代码/URL/图片保护；
- 页码、水印和私有符号清理；
- 长短段落、通用标题和未识别图片质量指标；
- 模型批次选择及相邻上下文；
- 图片短别名映射；
- 所有保护项门禁；
- 长度、标题和正文变化比例门禁；
- 单批失败回退且其他批继续；
- 上传开关关闭不额外调用模型；
- 已有文档草稿不修改正式段落；
- 应用事务、并发更新时间校验和重新向量化；
- 任务权限、取消、缓存过期和终态保护。

前端验证：

- 开关默认关闭并正确提交；
- 新进度阶段和质量摘要；
- 已有文档优化任务、终止按钮和刷新恢复；
- 前后对比及应用确认；
- 原文变化、任务失败和草稿过期提示；
- TypeScript 和 ESLint 通过。

## 完成标准

- 当前示例中的明确页码、`www.themegallery.com` 和 PowerPoint 私有项目符号被清理；独占数字保留供人工判断；
- “Python实例（一）”类标题被改写为具体知识点；
- 超过 1400 字的段落不进入最终优化结果；
- 图片、URL、代码、命令和图片说明无丢失、无新增、无重复；
- 未识别图片被保留并在报告中提示人工检查；
- 上传优化开关关闭时不增加模型调用；
- 已导入文档只有用户确认应用后才修改并重新向量化；
- 任一失败路径不破坏正式文档。
